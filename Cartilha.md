## 2. Introdução ao Git e GitHub

### O que é Git?

Git é um sistema de controle de versão utilizado para acompanhar as alterações realizadas em arquivos e projetos.

Ele permite identificar o que foi modificado, quando aconteceu a alteração e quem realizou a mudança.

### O que é GitHub?

GitHub é uma plataforma online que utiliza o Git para armazenar, organizar e compartilhar projetos.

Por meio dela, diferentes pessoas podem colaborar no mesmo projeto, mesmo estando em locais diferentes.

### Qual é a diferença entre Git e GitHub?

A principal diferença é que o Git é a ferramenta responsável pelo controle de versões, enquanto o GitHub é uma plataforma que permite hospedar repositórios e facilitar a colaboração entre usuários.

### O que é um repositório?

Um repositório é um espaço utilizado para armazenar e organizar os arquivos de um projeto.

Ele pode conter documentos, códigos, imagens e outros materiais necessários para o desenvolvimento de uma atividade.

### Repositório público e privado

Existem duas opções principais de visibilidade:

**Público:** qualquer pessoa pode visualizar o conteúdo do repositório.

**Privado:** somente o proprietário e as pessoas autorizadas podem acessar o conteúdo.

A escolha depende da finalidade do projeto e da necessidade de controlar quem poderá visualizar os arquivos.

## 3. Primeiros passos no GitHub

### Passo 1 — Criando uma conta

1. Acesse https://github.com.
2. Clique em Sign up.
3. Informe seu endereço de e-mail.
4. Crie uma senha.
5. Escolha um nome de usuário.
6. Finalize o cadastro seguindo as orientações da plataforma.

### Passo 2 — Criando um repositório

1. Entre na sua conta do GitHub.
2. Clique no botão New para criar um repositório.
3. Escolha um nome para o projeto.
4. Escreva uma breve descrição.
5. Escolha entre público ou privado.
6. Marque a opção Add a README file.
7. Clique em Create repository.

Pronto! Seu primeiro repositório foi criado.

### Passo 3 — O que é README?

README é um arquivo utilizado para apresentar as informações principais de um projeto.

Normalmente, ele contém:

- Nome do projeto.
- Objetivo.
- Integrantes.
- Explicação sobre o conteúdo.
- Links para outros arquivos.

Ele funciona como uma apresentação para quem acessa o repositório.

### Passo 4 — O que é Markdown?

Markdown é uma linguagem de marcação simples que permite formatar textos utilizando caracteres especiais.

Alguns exemplos:

**Título:**
# Meu projeto

**Subtítulo:**
## Apresentação

**Texto em negrito:**
**GitHub**

**Lista:**
- Primeiro item
- Segundo item
- Terceiro item

O Markdown facilita a organização e a leitura dos documentos diretamente no GitHub.

## 4. Arquivos e controle de versões

### Como adicionar um arquivo?

1. Entre no repositório desejado.
2. Clique em Add file.
3. Escolha Create new file para criar um arquivo ou Upload files para enviar um arquivo existente.
4. Digite o nome do arquivo.
5. Adicione o conteúdo, caso esteja criando um novo documento.
6. Clique em Commit changes para salvar.

### O que é Commit?

Commit é o registro de uma alteração realizada em um repositório.

Cada commit possui uma mensagem que explica o que foi modificado.

Exemplos de mensagens:

- Adiciona arquivo README.
- Atualiza informações do projeto.
- Corrige erro na cartilha.
- Adiciona imagens explicativas.

### O que é histórico de alterações?

É o registro dos commits realizados no repositório.

Por meio do histórico, podemos identificar quem realizou cada alteração e consultar as versões anteriores do projeto.

O histórico ajuda a acompanhar o desenvolvimento do trabalho e identificar as contribuições de cada integrante.

## 5. Colaboração no GitHub

Uma das principais vantagens do GitHub é permitir que diferentes pessoas trabalhem juntas no mesmo projeto.

### Como convidar colaboradores?

1. Acesse o repositório.
2. Clique em Settings.
3. Procure a opção Collaborators.
4. Clique em Add people.
5. Digite o nome de usuário da pessoa.
6. Envie o convite.
7. A pessoa deverá aceitar o convite para participar do repositório.

**Atenção:** nunca compartilhe sua senha com outros integrantes. Cada pessoa deve utilizar sua própria conta.

### O que é Branch?

Branch significa ramificação.

É uma versão separada do projeto utilizada para realizar alterações sem modificar diretamente a versão principal.

Por exemplo, um integrante pode criar uma branch para corrigir informações da cartilha antes de incorporar as mudanças ao projeto principal.

### O que é Pull Request?

Pull Request é uma solicitação para que as alterações realizadas em uma branch sejam analisadas e incorporadas à branch principal.

Ele permite que outros integrantes revisem o conteúdo antes de aprovar as mudanças.

### O que é Merge?

Merge é o processo de unir as alterações de uma branch à outra.

Após a revisão e aprovação de um Pull Request, o merge permite incorporar as modificações à versão principal do projeto.

### Entendendo o processo

1. Um integrante cria uma branch.
2. Realiza as alterações necessárias.
3. Registra um commit.
4. Abre um Pull Request.
5. Outro integrante analisa e comenta as mudanças.
6. Após a aprovação, é realizado o merge.
7. As alterações passam a fazer parte da branch principal.

## 6. Cuidados ao compartilhar arquivos

Ao utilizar o GitHub, é importante tomar alguns cuidados para proteger informações pessoais e evitar problemas.

Principais recomendações:

- Não publique senhas.
- Não compartilhe códigos de autenticação.
- Não publique tokens de acesso.
- Evite colocar dados pessoais desnecessários nos arquivos.
- Confira se o repositório está público ou privado.
- Revise os arquivos antes de enviá-los.
- Conceda acesso somente às pessoas necessárias.

Esses cuidados ajudam a manter os projetos organizados e mais seguros.

## 7. Prática e desafio para o leitor

Agora que você conhece os principais conceitos, chegou a hora de colocar o aprendizado em prática!

### Desafio: Crie seu primeiro repositório de estudos

Siga as instruções:

1. Crie um repositório com o nome estudos.
2. Escreva um README explicando o objetivo do repositório.
3. Adicione três assuntos que deseja aprender.
4. Crie um arquivo chamado anotacoes.md.
5. Escreva algumas anotações sobre um dos assuntos.
6. Registre uma alteração utilizando um commit com uma mensagem clara.
7. Compartilhe o repositório com um colega.
8. Confira se o colega conseguiu acessar e contribuir.

### Como saber se você concluiu?

Confira se:

- O repositório foi criado.
- O README apresenta o objetivo do projeto.
- Existem três assuntos para estudar.
- O arquivo de anotações foi adicionado.
- Existe pelo menos um commit.
- O colega conseguiu acessar o repositório.

Se todos os itens foram realizados, você concluiu o desafio!
